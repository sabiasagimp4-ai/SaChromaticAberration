# 色収差 (SaChromaticAberration)

YMM4 用の映像エフェクトプラグインです。Crate's Chromatic Aberration の見た目を参考に、
R/G/Bを別々の位置から1回ずつ参照して合成し、色の分離を作ります。画像全体を回転させて重ねる処理ではないため、Radialを上げても輪郭の形が大きく引き伸ばされません。

## パラメーター

| 名前 | 内容 |
| --- | --- |
| 収差 | 中心から外側へ色をずらす量 (px)。画面端の中点での値で、中心では 0、四隅ではさらに大きくなります。効果の主役。 |
| 減衰 | 中心からの距離に対する収差の増え方 (指数)。2 で距離の二乗に比例 = 中心が鮮明で周辺ほど大きく滲む、実レンズに近い見た目。0 にすると全面同じ量ずれます。 |
| ラジアル | 中心から色をずらす方向 (°)。0°は放射方向、90°は接線方向です。画像全体は回転しません。 |
| スケール | 色ごとに拡大率を変えてずらす量 (%)。奥行きのあるズレ。 |
| 中心X / 中心Y | ずれの中心位置 (px)。0px で画像中央。YMM4 の拡大縮小より前の、素材のピクセル空間で数えます。 |
| ステップ数 | 旧バージョンとの互換用です。現在の描画はR/G/Bの3サンプル固定です。 |
| 強さ | 元の映像との合成量 (%)。 |

正規化半径は縦横それぞれの半分の長さで割って求めるので、収差の等高線は画像と同じ縦横比の楕円になります。
画面端の中点が 1.0、四隅が約 1.41 で、減衰 2 のときの四隅の収差量は設定値の約 2 倍です。

既定値は収差 40px / 減衰 2.0 / ラジアル 8°です。RGB 3サンプルだけを使うため、以前の分光平均方式より描画負荷が小さく、色分離の輪郭も明確です。
参考画像のような柔らかい弧を出すには、素材自体がボケている必要があります。
細部が残っている素材に同じ設定を当てると、虹色は同じでも細かい模様がそのまま残り、より賑やかな絵になります。

収差・ラジアル・スケールがすべて 0 のときは、出力が入力と完全に一致します
(処理を早期終了するため)。

Radialは分離方向だけを回転させます。従来のように各角度の画像を連続的に回転して平均しないため、背景の線や人物の輪郭をぼかして引き伸ばす副作用を抑えています。

## ビルド

.NET 10 SDK と Windows SDK (fxc.exe) が必要です。

```powershell
$Ymm4DirPath = 'D:\YukkuriMovieMaker_v4_Lite\'
$FxcPath = 'C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\fxc.exe'
$D2DIncludePath = 'C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um'
dotnet build .\SaChromaticAberration.csproj -c Release "-p:YMM4DirPath=$Ymm4DirPath" "-p:FxcPath=$FxcPath" "-p:D2DIncludePath=$D2DIncludePath"
```

## インストール

`bin\Release\net10.0-windows10.0.19041.0\SaChromaticAberration.dll` を
YMM4 の `user\plugin\SaChromaticAberration\` にコピーして YMM4 を再起動します。

## 構成

- `Shaders/ChromaticAberration.hlsl` — RGB 3サンプルのピクセルシェーダー (ps_4_0)
- `ChromaticAberrationCustomEffect.cs` — D2D カスタムエフェクトと定数バッファ、入力全体の参照範囲指定
- `ChromaticAberrationProcessor.cs` — フレームごとのパラメーター更新
- `ChromaticAberrationEffect.cs` — YMM4 のエフェクト定義 (UI)

## 透明化・引き伸ばし修正 (2026-09-20)

- 画面外の参照座標を元画像の端の画素中心にクランプします。
- 出力アルファは元の画素アルファを維持します。不透明な入力が透明化しません。
- R/G/Bを別々にサンプリングし、各サンプルをアンプリマルチプライしてからチャンネルを取り出します。
- Radialは色分離ベクトルの角度として使い、画像全体を回転・平均しません。
- `ステップ数`は保存済み設定を壊さないために残していますが、描画には使用しません。

提供された1920×1080テストでは、従来方式で背景や人物が連続的に引き伸ばされることを確認しました。3チャンネル方式では同じ収差量でも輪郭のRGB分離だけが強くなり、画面全体の渦状の引き伸ばしは発生しません。

`python tests/radial_regression.py INPUT.jpg OUTPUT.png` でCPU参照テストを実行できます。これはHLSLの実行やYMM4の実機描画ではありません。
